# Migration tooling

The original plan in the TypeScript repo (`migration/progress-phase*.json`) was
generated by walking directories. Two problems came out of that:

1. **Completion was self-reported.** Phase 2 marked 231 modules done, but many
   targets hold invented APIs with no counterpart in the source, covered by
   tests written against the same invented API — so the suite stayed green.
2. **The order ignored dependencies.** Following the list means immediately
   importing modules that have not been ported yet, which is what pushes an
   automated loop into writing plausible-looking stubs.

These scripts rebuild the plan from the actual source trees.

## Usage

```bash
export OPENCLAW_TS_REPO=/path/to/openclaw   # TypeScript checkout
python migration/audit.py --json migration/audit.json
python migration/depgraph.py --json migration/plan.json
python scripts/migration_next_task.py --count 5
```

## What each script does

`ts_symbols.py` — shared regex extraction of exported symbols and import
specifiers from the TypeScript tree, plus the corresponding Python symbols.
Matching is loose (camelCase mapped to snake_case, plus the raw name) so
renames during porting still count as ported.

`audit.py` — grades every module by the share of exported symbols that have a
same-named Python definition:

| grade | meaning |
| --- | --- |
| `ported` | 85% or more of the exported API is present |
| `partial` | between 25% and 85% |
| `stub` | under 25%, so the target exists but is not a real port |
| `missing` | no Python target at all |
| `trivial` | the source directory exports nothing (holds only subdirectories) |

`depgraph.py` — resolves each module's imports back to the task that owns them,
condenses import cycles with Tarjan's algorithm, and emits tasks in dependency
order. Directory-level granularity collapses the core of the codebase into one
large cycle; within a cycle, tasks are ranked by how many other cycle members
import them, so the most foundational modules come first.

## Caveats

Symbol matching is a name-based proxy, not a semantic check. A module can score
well while behaving differently, and a heavily renamed port scores worse than
it deserves. Treat the grades as triage, not as a correctness signal.
